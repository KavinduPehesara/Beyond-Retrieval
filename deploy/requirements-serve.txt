# What the running product needs, and nothing else.
#
# requirements.txt pins the whole project, including the evaluation stack.
# None of that is reachable from a request: the API imports no heavy package
# at module load, and the only thing the product path pulls in at runtime is
# SPECTER2. Leaving asreview out alone takes about a gigabyte off the image.
#
# Verified by importing slr.api.app and checking sys.modules, and by grep for
# each heavy package across app/, slr/api, slr/services and slr/adapters:
#   asreview, scikit-learn  -- not imported anywhere on the product path
#   synergy-dataset, pandas -- slr/services/ingest.py only (corpus ingestion)
#   faiss-cpu               -- slr/services/dense_retrieve.py only; the
#                              product ranks with a numpy cosine, not FAISS
# Streamlit pulls pandas and altair in on its own account, so those arrive
# anyway; they are simply not asked for here.
#
# Pins match requirements.txt exactly. A ranking that changes because a
# library moved is the one failure that would invalidate every number in the
# report, so the deployed app runs the versions the report was written from.

# Checked by parsing every module reachable from the API and the page and
# listing what it imports: fourteen third-party names, all of them below.
#
# Two entries are here despite not appearing in that list. uvicorn is run as
# a command rather than imported, and pyyaml is kept because configs/ ships
# in the image and a dynamic load that the parse missed would take the
# server down for the sake of two hundred kilobytes.

# --- core ---
pydantic==2.9.2
pyyaml==6.0.2
python-dotenv==1.0.1
httpx==0.27.2
tenacity==9.0.0
numpy==2.5.3

# --- models ---
# OpenAI is called over plain HTTP, so there is no openai package here.
# See the 18 October note in CLAUDE.md for why google-genai is held at 0.3.0
# despite being yanked from the index; install needs --no-deps-safe handling
# only if the yank ever becomes a hard error.
google-genai==0.3.0

# --- ranking ---
# torch is installed separately in the Dockerfile from the CPU-only index;
# the default wheel carries a CUDA runtime nothing here can use. transformers
# is pinned although requirements.txt leaves it to be resolved, because the
# version that is actually installed is the one every ranking figure in the
# report came from, and letting a resolver pick a different one on the server
# is exactly the silent upgrade requirements.txt warns about.
sentence-transformers==3.2.1
adapters==1.3.0
transformers==4.57.6
